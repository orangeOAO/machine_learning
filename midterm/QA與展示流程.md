# 五分鐘 QA 準備

## 為什麼選垃圾分類？

它能把影像辨識技術連結到日常生活，六種材質類別也適合用圖片現場展示。本實驗的任務是判斷資料集標籤，沒有處理地區回收法規、髒污程度或多物件場景。

## 為什麼比較 CNN、ResNet18 和 DNN-TC？

自建小型 CNN 可以解釋卷積、池化與分類層，作為從頭訓練的基準。ResNet18 提供較成熟的影像特徵，適合研究小資料量下的遷移學習。兩者同時在架構及預訓練上不同，所以這是一組實作策略比較，不能聲稱它完全隔離了預訓練的效果。

DNN-TC 提供較大的 ResNeXt-101 骨幹與兩層分類頭，作為第三種策略。本實作採凍結骨幹與兩組固定增強特徵快取，並非作者完整微調流程，所以也不能把成績差異全部歸因於模型大小。

## 這是完整重現論文嗎？為什麼使用快取？

不是。核心分類架構參考論文，但使用 160px、既有 70/15/15 切分、15 輪 AdamW 及凍結骨幹。骨幹保持 eval 且參數不變，固定輸入的特徵可以重用，因此先提取兩組增強特徵再交替訓練分類頭。這會限制增強多樣性，與其他模型每輪重新取樣不同，簡報有公開此差異。CPU 訓練時間包含特徵擷取，不能用分類頭耗時取代總時間。

## 什麼是遷移學習？有微調全部層嗎？

把在 ImageNet 上學到的特徵用於新的六類任務。本專案凍結 ResNet18 骨幹與 BatchNorm 統計，只訓練最後的線性層，屬於特徵擷取型遷移學習。沒有對全部卷積層微調。

## 為什麼用 Macro F1？

Accuracy 是全部圖片中預測正確的比例，容易受大類別影響。每類 F1 同時考慮 precision 和 recall，macro F1 再將六類等權平均，讓只有少量圖片的其他垃圾類別也有同等權重。

## 三個資料集合的差別？

訓練集更新模型權重；驗證集比較不同 epoch 並選擇 checkpoint；測試集只在訓練設定確定後評估。若反覆根據測試集結果改模型，就會讓測試集變成另一個驗證集。

## 如何防止資料洩漏？

下載後先比較解碼 RGB 影像的 SHA-256。發現三組相同影像卻有不同類別的資料，因此排除六張衝突圖片，再固定分層切分。沒有完整的物件身分資訊，因此同物件不同角度或近似圖片仍可能跨集合，這是研究限制。

## 為什麼可能訓練準確率低於驗證準確率？

訓練時計入隨機資料增強，CNN 也啟用 Dropout；驗證時沒有這些擾動。而且訓練指標是該 epoch 逐步更新權重期間累計，驗證是 epoch 結束後的模型，不是完全相同的條件。

## 為什麼不用 GPU？

目前環境是 PyTorch 2.2.2，其預編譯 CUDA 核心不支援本機 RTX 5060 的架構。實際 CUDA 運算測試失敗，因此使用 CPU，確保既有課程版本可以執行。CUDA 可見不代表所有計算核心都相容。

## 模型有 95% 分數就代表 95% 會答對嗎？

不一定。這是 softmax 分數，未做校準，對資料分布以外的圖片仍可能非常有信心。模型沒有未知類別，所有輸入都會被迫分到六類之一。

## 能直接部署在真實回收站嗎？

目前不能從本實驗推論真實場域效果。資料多為白背景、單一物件，與複雜背景、多物件、遮擋、髒污和不同攝影設備有落差。需要額外的獨立場域資料與測試。

## 實驗有哪些可改進的地方？

多個 seed 重複實驗來衡量波動；加入隨機初始化 ResNet18，隔離預訓練的效果；加入生活照片測試集；嘗試部分解凍後微調，並僅用驗證集選擇超參數。

# 三分鐘 Demo 操作

1. 報告前啟動 `python midterm/demo.py`，確認瀏覽器開啟 `http://localhost:8765`。
2. 從 `demo_samples` 選 `all_correct` 開頭的圖片。說明真實類別，再按「比較三個模型」。約 45 秒。
3. 選 `dnntc_correct_others_wrong` 圖片，比較三模型前幾名預測。約 45 秒。若沒有此類案例，使用答案檔中實際存在的案例。
4. 選 `dnntc_wrong` 圖片，說明較大的模型也會犯錯。約 45 秒。
5. 用剩下時間提醒 softmax 與真實機率的差別，以及生活場景限制。約 45 秒。

這些範例是為了展示而挑選的測試集圖片，不能用它們取代完整測試集指標。`answers.json` 保存真實類別與三模型預測。若現場無法啟動，使用結果圖與已保存的 predictions.csv 作為備案。
